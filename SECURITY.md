# Security Policy

## Supported versions

Personal Librarian is pre-1.0. Security and privacy fixes target the latest public code; older snapshots and locally generated binaries are not maintained as separate supported release lines. This policy may evolve as the project matures.

## Reporting a vulnerability

Prefer [GitHub private vulnerability reporting](https://github.com/dreamingfree09/personal-librarian/security/advisories/new) when it is enabled. If it is unavailable, use an appropriate private contact channel once one is listed by the project owner. Do not disclose a suspected vulnerability in a public issue.

Never attach or disclose real private photos, videos, catalogue databases, backup files, credentials, local filesystem paths, device identifiers, or other personal-library data. Provide the smallest reproduction possible using synthetic data.

A security or privacy report may include, for example:

- unintended file mutation, deletion, overwrite, or path-boundary bypass;
- exposure of catalogue, media, credential, backup, or local-system information;
- unsafe handling of untrusted catalogue fields, paths, manifests, or imported evidence; or
- a weakness that undermines approval, audit, quarantine, backup, or recovery safeguards.

Include the affected version or commit, expected and actual behaviour, minimal reproduction steps, and a concise impact assessment. Reports will be reviewed and handled according to severity and maintainer availability, but no fixed response-time SLA is promised.
